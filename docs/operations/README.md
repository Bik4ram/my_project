# SemRAG Operations Runbook

This directory contains the on-call runbooks for SemRAG operators. Each
runbook covers one failure mode (database outage, LLM outage, etc.) with:

- **Symptom** — what alerts or logs you'll see.
- **Triage** — how to confirm the failure mode and rule out
  alternatives.
- **Mitigation** — concrete steps to restore service.
- **Verification** — how to confirm the fix worked.

For Wave 3, the following runbooks are provided:

| Runbook | Use when |
| --- | --- |
| [database-outage.md](database-outage.md) | `SemRAGDatabaseUnavailable` alert fires, or `/readyz` reports `database: down` |
| [llm-outage.md](llm-outage.md) | `SemRAGLLMUnavailable` alert fires, or `/answer` requests time out |
| [embedding-failure.md](embedding-failure.md) | `SemRAGEmbeddingUnavailable` alert fires, indexing stalls in the embedding stage |
| [indexing-failure.md](indexing-failure.md) | `SemRAGIndexingJobsFailing` fires, or `/v1/projects/{id}/index` returns 5xx |
| [job-backlog.md](job-backlog.md) | `SemRAGIndexingJobBacklog` fires, queue rate > completion rate |
| [high-latency.md](high-latency.md) | `SemRAGHighRequestLatencyP95`, `SemRAGHighLLMLatencyP95`, or `SemRAGHighEmbeddingLatencyP95` |
| [memory-exhaustion.md](memory-exhaustion.md) | `SemRAGHighMemoryUsage` fires, pod is OOMKilled |
| [rollback.md](rollback.md) | General rollback guide for SemRAG releases |
| [escalation.md](escalation.md) | When and how to escalate to the platform team |

## Operational Conventions

- **All API requests are JSON over HTTPS** unless you see otherwise in
  a specific runbook.
- **`X-Request-ID`** is generated by the API on inbound requests and
  echoed in every log line. Use it to correlate a user-reported issue
  with the matching log entries.
- **`/readyz`** is the single source of truth for "should this pod
  receive traffic?". A 503 from `/readyz` removes the pod from the
  Kubernetes service endpoints.
- **`/metrics`** is exposed by every pod and scraped by Prometheus
  every 15 seconds. The alert rules in
  `deploy/monitoring/prometheus/rules/semrag.yml` cover the failure
  modes described here.
